أنت Senior Flutter Architect وSenior Software Engineer.

لدي مشروع Flutter مكتمل يعمل بالفعل، وأريد تحديثه وتحسينه دون إعادة بنائه من الصفر.

مهم جداً:

❌ لا تعيد إنشاء المشروع.
❌ لا تغير المعمارية الحالية إلا عند الضرورة.
❌ لا تحذف أي ميزة موجودة.
❌ لا تكسر أي شاشة أو API أو منطق عمل.

اعمل فقط على إضافة وتحديث الميزات التالية بطريقة احترافية وقابلة للتوسع (Non-Breaking Upgrade).

==================================================
أولاً: Authentication
==================================================

استبدل نظام تسجيل الدخول الحالي بالكامل بـ Google Sign-In فقط.

المتطلبات:

- Google Sign-In هو الطريقة الوحيدة للدخول.
- إزالة Login بالبريد وكلمة المرور.
- إزالة Register.
- إزالة Forgot Password.
- إزالة OTP.
- إنشاء المستخدم تلقائياً عند أول دخول.
- تحديث بيانات المستخدم عند كل تسجيل دخول.
- حفظ:
  - Google ID
  - الاسم
  - البريد
  - الصورة
  - آخر تسجيل دخول
- دعم Refresh Token.
- دعم JWT.
- تسجيل خروج آمن.

==================================================
الحادي عشر: المشروع
==================================================

قم بتحليل المشروع الحالي أولاً.

ثم حدد الملفات التي تحتاج إلى تعديل.

ولا تقم بإنشاء ملفات جديدة إذا كان بالإمكان إعادة استخدام الموجودة.

إذا احتجت لإضافة ملفات جديدة فاذكر السبب.

==================================================
الثاني عشر: قبل كتابة أي كود
==================================================

قم أولاً بإنتاج:

1- تحليل المشروع الحالي.

2- ما الذي سيتم تعديله.

3- الملفات التي ستتغير.

4- الملفات الجديدة.

5- Dependency Graph.

6- خطة التنفيذ.

7- ترتيب التنفيذ خطوة بخطوة.

ثم بعد موافقتي ابدأ بالتنفيذ.

==================================================
الثالث عشر: الجودة
==================================================

أي كود جديد يجب أن:

- يتوافق مع Clean Architecture.
- يتوافق مع Feature First.
- لا يكرر الكود.
- قابل للاختبار.
- قابل للتوسع.
- يحافظ على جميع الميزات الحالية.
- لا يسبب Breaking Changes.

اعتبر نفسك تعمل على منتج SaaS عالمي قيد الإنتاج، وأي تعديل يجب أن يكون احترافياً، متوافقاً مع أفضل الممارسات، وقابلاً للصيانة والتوسع مستقبلاً.
